### ADR-001-speaker-segments: Формирование speaker сегмента по word-level assignment без пересборки сегментов

* **Статус:** accepted
* **Область:** worker-transcription, WhisperX diarization
* **Связанные требования:** FR-0018-03-TRSC, FR-0018-05-DIAR
* **Решение:** сохранять сегменты, сформированные WhisperX после alignment, и не пересобирать текст из отдельных слов. Первым шагом использовать Silero VAD при сохранении штатного алгоритма WhisperX формирования segments и `assign_word_speakers()`. Переопределение `segment.speaker` по `words[].speaker` применять только как следующий шаг, если VAD-first стратегия не обеспечивает требуемое качество.


#### Выбранное решение

Выбрана стратегия **минимального изменения upstream WhisperX**, чтобы снизить риски сопровождения, диагностики и дальнейшего обновления WhisperX.

Первый шаг — заменить только VAD на **Silero**, сохранив штатные WhisperX segments после alignment и стандартный `assign_word_speakers()`. Основание — эксперимент на исследуемой записи с той же моделью: при замене только VAD на Silero проблемный сегмент получил корректного speaker без изменения алгоритма определения segments и speaker assignment в WhisperX.

Если VAD-first стратегия не обеспечит требуемое качество, следующим шагом рассматривается локальное переопределение только `segment.speaker` по `words[].speaker` без пересборки текста. Для устойчивости учитывается не суммарное количество слов спикера по всему сегменту, а **непрерывная последовательность подряд идущих words одного speaker**.

Риск текущего выбора: эксперимент с Silero выполнен на небольшой выборке. Полученный результат подтверждает применимость стратегии для найденного дефекта, но не доказывает общее преимущество Silero на всех типах записей.

#### Контекст

WhisperX последовательно формирует текст и связывает его с результатом диаризации:

```
audio
  ↓
VAD
(определяет интервалы, в которых присутствует речь)
out: speech regions[{start,end}]
  ↓
ASR / Whisper
(распознаёт речь и формирует текстовые сегменты)
out: segments[{start,end,text}]
  ↓
alignment
(уточняет временные границы распознанных слов)
out: segments[{start,end,text,words[{word,start,end,score}]}]
  ↓
diarization
(определяет интервалы речи каждого спикера независимо от текста)
out: diarization[{start,end,speaker}]
  ↓
assign_word_speakers()
(сопоставляет intervals segments/words с diarization intervals)
out: segments[{start,end,text,speaker,words[{word,start,end,score,speaker}]}]
```
`assign_word_speakers()` определяет `segment.speaker` и `word.speaker` независимо.

Для каждого объекта — сначала сегмента, затем каждого слова — выполняется одна и та же операция:

1. Берётся временной интервал объекта `[start, end]`.
2. Он сравнивается с интервалами речи каждого спикера, полученными диаризацией.
3. Для каждого пересекающегося интервала вычисляется длительность пересечения:

```text
intersection =
min(object.end, diarization.end)
-
max(object.start, diarization.start)
```

4. Для каждого спикера складывается длительность всех его пересечений с объектом.
5. Объект получает `speaker` того участника, для которого получена наибольшая суммарная длительность пересечения.

Таким образом, `segment.speaker` **не вычисляется из `words[].speaker`**.

Количество слов каждого спикера также не участвует в определении `segment.speaker`.

#### Почему сегмент может получить SPEAKER_00, хотя большинство слов — SPEAKER_02

Проблемный результат (говорит SPEAKER_02):

```text
segment:
27.176 -------------------------------- 28.516
"Это с нулями или нау?"

segment.speaker:
SPEAKER_00

words:
Это      → SPEAKER_02
с        → SPEAKER_02
нулями   → SPEAKER_02
или      → SPEAKER_02
нау?     → SPEAKER_00
```

На первый взгляд результат кажется противоречивым:

```text
SPEAKER_02 = 4 слова
SPEAKER_00 = 1 слово
```

Однако WhisperX не использует это соотношение для определения `segment.speaker`.

Он выполняет два независимых расчёта.

Для слова `"Это"` сравнивается только интервал:

```text
27.176–27.316
```

Для `"с"`:

```text
27.336–27.396
```

и аналогично для остальных слов.

Первые четыре коротких интервала сильнее пересекаются с интервалами речи `SPEAKER_02`, поэтому эти слова получают `SPEAKER_02`.

Последнее слово:

```text
"нау?"
28.016–28.516
```

сильнее пересекается с речью `SPEAKER_00`, поэтому получает `SPEAKER_00`.

Для всего сегмента WhisperX выполняет **новый независимый расчёт**:

```text
27.176–28.516
```

Он складывает длительность пересечения этого полного интервала:

```text
с интервалами SPEAKER_02
и
с интервалами SPEAKER_00
```

и выбирает спикера с большей суммой.

Упрощённый пример:

```text
segment:
27.176 -------------------------------- 28.516

SPEAKER_02:
========================

SPEAKER_00:
             =============================
```

Для отдельных слов результат может быть:

```text
Это      → большая часть интервала совпала с SPEAKER_02
с        → большая часть интервала совпала с SPEAKER_02
нулями   → большая часть интервала совпала с SPEAKER_02
или      → большая часть интервала совпала с SPEAKER_02
нау?     → большая часть интервала совпала с SPEAKER_00
```

Но для полного сегмента, например:

```text
суммарное пересечение segment ↔ SPEAKER_02 = 0.9 s
суммарное пересечение segment ↔ SPEAKER_00 = 1.0 s
```

WhisperX назначит:

```text
segment.speaker = SPEAKER_00
```

Числа выше приведены только для иллюстрации механизма. Для исследуемой записи исходные интервалы diarization не сохранены, поэтому фактические длительности пересечений неизвестны.

Однако сам результат:

```text
segment.speaker = SPEAKER_00
```

означает, что при расчёте для полного временного интервала сегмента WhisperX предпочёл `SPEAKER_00`, независимо от результатов расчёта для отдельных слов.

При одновременной речи это особенно важно: интервалы `SPEAKER_00` и `SPEAKER_02` могут существовать одновременно. Поэтому длительности их пересечения с сегментом не делят длительность сегмента между собой.

Например, один интервал длительностью 1.34 s может одновременно пересекаться:

```text
с SPEAKER_02 на 0.9 s
и
с SPEAKER_00 на 1.0 s
```

Это допустимо, потому что диаризация фиксирует одновременное присутствие двух голосов.

Следовательно, большинство `words[].speaker = SPEAKER_02` не противоречит `segment.speaker = SPEAKER_00`: эти значения получены независимыми расчётами для интервалов разного размера.

Для рассматриваемой фразы известно из исходного аудио, что её произносит `SPEAKER_02`. Поэтому в данном случае результат whole-segment расчёта WhisperX является ошибочным для задачи атрибуции текста.

#### Почему пересборка сегментов по words даёт ошибки

Один из вариантов формирования результата — игнорировать исходные сегменты Whisper и заново группировать слова по `word.speaker`.

Для рассматриваемого примера:

```text
Это      02
с        02
нулями   02
или      02
нау?     00
```

такой алгоритм построит:

```text
SPEAKER_02: Это с нулями или
SPEAKER_00: нау?
```

Но в исходном аудио вся фраза:

```text
"Это с нулями или нау?"
```

принадлежит `SPEAKER_02`.

Причина ошибки — второму участнику не обязательно принадлежит слово, если его голос присутствует в тот же момент времени.

Типичная ситуация на границе реплик:

```text
SPEAKER_02: Это с нулями или нау?
                              ──────▶

SPEAKER_00:                    Нет, ...
                              ─────────▶
```

Второй участник начинает отвечать до полного окончания предыдущей фразы.

Диаризация корректно фиксирует его голос.

Интервал последнего слова первой реплики пересекается с речью обоих участников. Если речь `SPEAKER_00` занимает в этом интервале большую длительность, `assign_word_speakers()` назначает слову:

```text
word.speaker = SPEAKER_00
```

Это локальная ошибка атрибуции слова, но при пересборке по `words[].speaker` она превращается в структурную ошибку:

```text
одна неверная метка слова
        ↓
создание нового сегмента
        ↓
перенос окончания фразы другому спикеру
```

В результате:

* конец законченной фразы получает неверного спикера;
* появляются сегменты из одного-двух слов;
* одна реплика искусственно разбивается на несколько;
* нарушается пунктуационная и смысловая целостность текста;
* postprocess и summarization получают уже искажённую структуру диалога.

Поэтому `word.speaker` полезен как локальный сигнал для определения speaker, но недостаточно надёжен как основание для изменения границ текста.

#### Почему сегменты Whisper следует сохранять

Whisper формирует текстовый сегмент во время распознавания речи и использует при этом акустический и языковой контекст.

```text
Whisper segment
├── start
├── end
├── text
└── words[]
```

В результате в сегменте уже зафиксированы:

* последовательность слов;
* связность фразы;
* пунктуация;
* границы декодирования.

Диаризация решает другую задачу: определяет, кто говорит в определённые моменты времени.

Поэтому ответственность компонентов разделяется следующим образом:

```text
Whisper + alignment
→ определяют текст, состав слов и временные границы сегмента

Diarization + assign_word_speakers()
→ определяют speaker для этого текста
```

Диаризация не должна изменять структуру текста при каждом локальном изменении `word.speaker`.

#### Как VAD влияет на назначение speaker

VAD находится перед Whisper:

```text
audio
  ↓
VAD
(определяет интервалы речи)
  ↓
Whisper
(формирует сегменты внутри полученных речевых интервалов)
  ↓
alignment
(уточняет временные границы слов)
  ↓
assign_word_speakers()
(сравнивает полученные границы с интервалами diarization)
```

Поэтому VAD не назначает speaker непосредственно.

Он влияет на результат через границы сегментов.

Если два VAD по-разному определили начало или конец речевого участка:

```text
VAD A:
27.176 ------------------------------- 28.516

VAD B:
27.176 ---------------------- 28.100
```

Whisper может сформировать разные сегменты.

После alignment `assign_word_speakers()` будет сравнивать с интервалами diarization уже разные временные интервалы.

Например:

```text
segment A:
SPEAKER_02 пересекается 0.9 s
SPEAKER_00 пересекается 1.0 s
→ SPEAKER_00

segment B:
SPEAKER_02 пересекается 0.8 s
SPEAKER_00 пересекается 0.4 s
→ SPEAKER_02
```

Следовательно:

```text
другие границы VAD
→ другие границы Whisper segment
→ другие длительности пересечения с diarization
→ возможен другой segment.speaker
```

Именно поэтому Silero VAD может дать правильный `SPEAKER_02` на исследуемом участке, хотя алгоритм `assign_word_speakers()` остаётся тем же.

#### Риски и ограничения смены VAD

На исследуемом участке Silero VAD дал правильный результат.

Однако установлен только один факт:

```text
этот аудиофрагмент:
Silero → SPEAKER_02
текущий VAD → SPEAKER_00
```

Из этого нельзя сделать вывод:

```text
Silero → лучше на всех записях
```

Замена VAD изменяет раннюю стадию конвейера и поэтому может повлиять не только на speaker:

```text
VAD
→ интервалы, переданные Whisper
→ ASR segmentation
→ распознанный текст
→ alignment
→ таймкоды
→ speaker assignment
```

Возможны изменения:

* границ сегментов;
* количества сегментов;
* распознавания коротких реплик;
* распознавания тихой речи;
* поведения на шумных участках;
* самого распознанного текста;
* word timestamps.

Наблюдаемая ошибка находится значительно позже:

```text
текст уже распознан
→ слова уже выровнены по времени
→ diarization уже выполнена
→ words[].speaker уже рассчитаны
→ неверно выбран только итоговый segment.speaker
```

Поэтому изменение VAD имеет более широкую область воздействия, чем локальное исправление выбора `segment.speaker`, и несёт больший regression-риск.

Несмотря на этот риск, текущая стратегия выбирает **Silero как первый шаг**, потому что это минимальное изменение относительно upstream: меняется штатно поддерживаемая VAD-конфигурация, а алгоритмы формирования segments и `assign_word_speakers()` остаются стандартными WhisperX.

При этом выборка эксперимента мала. Silero не считается доказанно лучшим VAD в общем случае; его преимущество должно подтверждаться дальнейшим regression-тестированием на записях разных типов.

#### Рассмотренные варианты

##### Вариант A — пересобирать сегменты по `words[].speaker`

```text
02 02 02 02 00
        ↓
"Это с нулями или" → 02
"нау?"              → 00
```

Недостаток: одна ошибочная метка слова изменяет структуру текста.

**Решение:** отклонено.

##### Вариант B — заменить текущий VAD на Silero

На исследованном участке:

```text
Silero → правильный speaker
```

Но изменение VAD влияет на весь ASR pipeline, а качество на других записях не проверено.

**Решение:** использовать как первый шаг исправления. Это сохраняет максимальное использование upstream WhisperX; риск широкой области воздействия принимается и должен контролироваться regression-тестами.

##### Вариант C — сохранять Whisper segment и уточнять только `segment.speaker`

```text
segment.speaker от WhisperX:
00

words:
02 02 02 02 00

большинство words:
02

итоговый segment.speaker:
02
```

При этом исходный сегмент не изменяется.

**Решение:** сохранить как следующий шаг, если Silero VAD не обеспечивает требуемое качество.

#### Следующий шаг при недостаточном качестве VAD-first

Основной единицей diarized transcript остаётся сегмент WhisperX.

```text
segment
├── start        → не изменяется
├── end          → не изменяется
├── text         → не изменяется
├── words[]      → не перегруппировываются
└── speaker      → может быть уточнён
```

После стандартного `assign_word_speakers()` этот fallback-алгоритм определяется следующим образом:

1. Слова текущего сегмента рассматриваются в исходном порядке.
2. Формируются непрерывные последовательности подряд идущих words с одинаковым `word.speaker`.
3. Слова без `word.speaker` разрывают последовательность и не присоединяются к соседним группам.
4. Последовательности одного speaker, разделённые словами другого speaker или словами без speaker, **не суммируются**.
5. Определяется самая длинная непрерывная последовательность.
6. `segment.speaker` переопределяется только если одна уникальная последовательность одного speaker содержит строго больше половины **всех words сегмента**.
7. Если такого большинства нет, сохраняется `segment.speaker`, вычисленный WhisperX.
8. Сегмент не разделяется и не пересобирается.

```python
words = segment.get("words", [])

best_speaker = None
best_run = 0
current_speaker = None
current_run = 0

for word in words:
    speaker = word.get("speaker")

    if speaker is None:
        current_speaker = None
        current_run = 0
        continue

    if speaker == current_speaker:
        current_run += 1
    else:
        current_speaker = speaker
        current_run = 1

    if current_run > best_run:
        best_speaker = speaker
        best_run = current_run

if best_speaker is not None and best_run > len(words) / 2:
    segment["speaker"] = best_speaker
```

Такой критерий устойчивее простой суммы labels по всему сегменту. Например:

```text
02 00 02 00 02
```

не приводит к override, хотя `02` встречается три раза из пяти: ни одна непрерывная последовательность `02` не образует большинство.

Для проблемного примера:

```text
Это      → SPEAKER_02
с        → SPEAKER_02
нулями   → SPEAKER_02
или      → SPEAKER_02
нау?     → SPEAKER_00

непрерывная последовательность SPEAKER_02 = 4 слова
следующая последовательность SPEAKER_00 = 1 слово

4 > 5 / 2

→ segment.speaker = SPEAKER_02
```

Получаем:

```text
SPEAKER_02:
"Это с нулями или нау?"
```

вместо:

```text
SPEAKER_02:
"Это с нулями или"

SPEAKER_00:
"нау?"
```

`word.score` в расчёте не используется, поскольку он характеризует качество alignment слова, а не достоверность определения спикера.

#### Почему fallback локализован на уровне segment.speaker

Подтверждённый дефект состоит не в неправильной структуре текста.

Whisper уже сформировал корректную фразу:

```text
"Это с нулями или нау?"
```

Проблема состоит только в том, что независимый расчёт для полного временного интервала присвоил этой фразе:

```text
SPEAKER_00
```

хотя локальные назначения четырёх из пяти слов и исходное аудио указывают на:

```text
SPEAKER_02
```

Если после VAD-first стратегии остаётся этот класс дефектов, fallback изменяет только поле:

```text
segment.speaker
```

Не изменяются:

```text
VAD
ASR
alignment
segment boundaries
segment text
word boundaries
```

Такой fallback локализует custom-логику в той части конвейера, где непосредственно проявляется дефект, и не создаёт дополнительных изменений структуры текста.

#### Последствия

Для fallback-варианта C положительные стороны остаются следующими:

Положительные:

* сохраняется исходная структура текста Whisper;
* единичная ошибка `word.speaker` не переносит конец фразы другому спикеру;
* несколько согласованных `word.speaker` могут исправить ошибочный `segment.speaker`;
* изменение не влияет на VAD, ASR и alignment;
* исходные `words[].speaker` сохраняются для диагностики.

Ограничения:

* один segment по-прежнему имеет только одного итогового speaker;
* реальная смена speaker внутри одного Whisper segment автоматически не создаёт два сегмента;
* при отсутствии абсолютного большинства используется исходный `segment.speaker`;
* результат зависит от качества word-level alignment и diarization.

Принимается компромисс:

```text
сохранять целостность распознанной фразы
важнее,
чем разрезать её при каждом локальном изменении word.speaker
```

#### Инварианты

Если fallback-вариант C будет реализован:

* количество aligned segments не меняется;
* `segment.start` не меняется;
* `segment.end` не меняется;
* `segment.text` не пересобирается;
* порядок `segment.words` не меняется;
* `words[].speaker` сохраняется;
* изменяться может только итоговый `segment.speaker`;
* без непрерывной последовательности одного speaker длиной больше половины всех words сохраняется исходный `segment.speaker`.

#### Проверка решения

Для VAD-first стратегии первым regression case является исходный проблемный фрагмент: после смены VAD на Silero ожидается корректный `segment.speaker` при неизменном стандартном `assign_word_speakers()`.

Если реализуется fallback-вариант C, обязательный regression case:

```text
text:
"Это с нулями или нау?"

raw segment.speaker:
SPEAKER_00

words:
02 02 02 02 00

expected:
segment.speaker = SPEAKER_02
segments = 1
text не изменён
```

Дополнительно проверяются:

* последовательная речь без пересечения;
* начало следующей реплики до окончания предыдущей;
* ошибочный speaker последнего слова;
* ошибочный speaker одного слова внутри фразы;
* короткие ответы «да», «нет», «ага»;
* отсутствующий `word.speaker` у части слов;
* равное количество слов двух спикеров;
* три и более спикера;
* чередование `02 00 02 00 02` — override не выполняется;
* две отдельные последовательности одного speaker не суммируются;
* отсутствующий `word.speaker` разрывает последовательность.

#### Условия пересмотра

Решение пересматривается, если:

* тестирование покажет, что большинство `word.speaker` регулярно заменяет правильный `segment.speaker` на неправильный;
* один Whisper segment регулярно содержит две самостоятельные реплики разных спикеров;
* появится надёжная оценка вероятности принадлежности всего текста сегмента конкретному спикеру;
* сравнительное тестирование VAD на наборе записей покажет устойчивое преимущество другого VAD без ухудшения ASR и alignment.

Текущая стратегия — скорость реализации и простота сопровождения за счёт максимального использования upstream WhisperX. Поэтому первым шагом выбран Silero VAD при сохранении стандартных WhisperX segments и `assign_word_speakers()`. Выбор основан на успешном эксперименте на найденном дефекте, но считается предварительным из-за малой выборки.

Переопределение `segment.speaker` по `words[].speaker` остаётся следующим шагом только при недостаточном качестве VAD-first стратегии; при его реализации используется критерий непрерывной последовательности подряд идущих words одного speaker, а не простая сумма labels по всему сегменту.
