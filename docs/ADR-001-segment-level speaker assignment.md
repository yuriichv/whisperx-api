# ADR-001 — Использовать segment-level speaker assignment при формировании diarized output

* **Статус:** Accepted
* **Контекст:** `whisperx-api`, формирование реплик после WhisperX alignment и diarization.

## Проблема
WhisperX назначает speaker независимо для aligned segment и для каждого слова. На границе смены спикеров возможен конфликт:

```text
segment.speaker = SPEAKER_00

words:
Просто   → SPEAKER_00
интовый  → SPEAKER_00
массив   → SPEAKER_02
```

Наблюдался аналогичный зеркальный случай:

```text
эту      → SPEAKER_02
длину    → SPEAKER_00
```

При этом последнее слово имеет высокий alignment score (`0.901`), поэтому проблема не сводится к низкой уверенности alignment.

**Эффект**: 
Текущий `whisperx-api` использует смену `word.speaker` как основание для разбиения реплики. В результате локальная погрешность около speaker boundary превращается в заметную ошибку:

```text
SPEAKER_00: Просто интовый
SPEAKER_02: массив. Так, ...
```

Локальная реализация использует `segment.speaker` для вывода всего aligned segment и такого дефекта не проявляет.

## Источник проблемы

Наиболее вероятный источник — взаимодействие двух независимых временных моделей:

```text
forced alignment word timestamps
        +
pyannote speaker boundaries
        ↓
max-overlap word speaker assignment
```

Последнее слово предложения часто имеет относительно длинный aligned interval. Если внутрь него попадает начало следующего diarization turn, `assign_word_speakers()` может назначить слову следующего speaker.

`WHISPERX_FILL_NEAREST` проблему не решает: ошибка возникает при реальном overlap, а не при отсутствии diarization interval.

## Вариант 1 — Stabilized word-level diarization

Оставить `word.speaker`, но не считать одиночную смену speaker достаточной для новой реплики.

Например:

```text
00 00 02       → считать пограничным noise
00 00 02 02 02 → считать реальной сменой speaker
```

Можно учитывать количество последовательных слов, их длительность, соседние segments и `segment.speaker`.

**Плюсы:**

* потенциально корректно обрабатывает реальную смену speaker внутри одного aligned segment;
* сохраняет максимальную детализацию word-level diarization.

**Минусы:**

* появляются эвристики и пороговые параметры;
* сложнее тестирование;
* трудно подобрать универсальные thresholds;
* возрастает вероятность новых edge cases;
* пока нет подтверждения, что реальные смены вида `00 00 02 02 02` внутри одного aligned segment достаточно часты, чтобы оправдать сложность.

## Вариант 2 — Segment-level speaker assignment

Для формирования `diarized_json` и текстовых реплик использовать только:

```text
segment.speaker
```

`words[].speaker` сохранять в `verbose_json` как диагностическую информацию, но не использовать для разбиения реплики.

Таким образом:

```text
segment.speaker = 00
words            = 00 00 02
```

даёт:

```text
SPEAKER_00: Просто интовый массив.
```

## Решение

Для первой реализации выбрать **вариант 2 — segment-level speaker assignment**.

Причина — принцип минимальной достаточности. Наблюдаемые реальные дефекты вызваны именно чрезмерным доверием к одиночному `word.speaker`. Segment-level подход уже используется локальной реализацией и устраняет этот класс ошибок без дополнительных эвристик.

Обработка настоящих speaker transitions внутри одного aligned segment (`00 00 02 02 02`) сейчас считается возможным, но неподтверждённым edge case. Реализация сложного stabilization algorithm до появления измеримых примеров является overengineering.

## Принятый trade-off

Редкая реальная смена speaker внутри одного aligned segment может быть полностью отнесена к `segment.speaker`.

Это принимается в обмен на:

* более устойчивый diarized output;
* простой и предсказуемый алгоритм;
* отсутствие дополнительных thresholds;
* соответствие уже проверенному поведению локальной реализации.

## Условие пересмотра

Вернуться к stabilized word-level diarization, если на реальном корпусе будет обнаружено значимое количество случаев, где один aligned segment содержит несколько настоящих speaker turns и segment-level assignment приводит к заметным ошибкам.
